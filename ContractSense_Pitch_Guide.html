Smart Contract Risk Analyser for Indian MSMEs | SIH Problem SW-59

1. The 60-Second Elevator Pitch (Memorize This)

"India has 63 million MSMEs. Every day, hundreds of thousands of them sign vendor contracts drafted by large corporates — without a single lawyer reviewing it. Hiring a lawyer costs ₹5,000–₹50,000 per contract. MSMEs simply can't afford that. So they sign blindly and get trapped by predatory clauses they don't understand.

ContractSense is an AI-powered contract risk analyser built specifically for the Indian legal context. An MSME owner uploads their contract PDF, and within seconds they get a full risk report in plain language — which clauses are dangerous, exactly which section of the MSME Development Act or Indian Contract Act is being violated, and a precise redline suggestion of how to fix it.

We built it with a dual-engine architecture: an AI mode for deep contextual analysis, and a completely offline, zero-API mode that works even without internet — giving MSMEs in rural India and sensitive industrial corridors full data privacy. Their documents never leave their server."

2. Technical Architecture (Explain This Confidently)

ContractSense has a full-stack web application built across three technology layers:

Frontend — Next.js 14 (TypeScript / React)

  • Runs entirely in the browser at localhost:3000
  • Built with TypeScript — a statically typed superset of JavaScript that prevents runtime bugs at compile time
  • Pages: Landing page, Dashboard (4 tools), and a dedicated Report page
  • Uses CSS Custom Properties (variables) for a consistent enterprise-grade dark theme
  • The UI is fully bilingual — switches between English and Hindi at runtime without any page reload
  • All state management is done with React hooks (useState, useEffect) — no Redux or external state library needed

Backend — Python / Flask

  • Runs at localhost:8000
  • Flask is a lightweight Python web framework — perfect for building REST APIs
  • Handles PDF upload, text extraction, AI calls, and offline analysis
  • Uses SQLite (via a db.py module) for storing user sessions and OTPs — a file-based database requiring zero setup
  • All API endpoints are properly CORS-configured for the frontend to call them

Database — SQLite + JWT Auth

  • auth.py implements a full OTP-based email login system
  • Users enter their email → receive a 6-digit OTP → OTP verified against the database → a JWT (JSON Web Token) is issued
  • JWT is a cryptographically signed token (HS256 algorithm) that proves identity without storing sessions server-side
  • OTPs are auto-deleted after verification — no lingering sensitive data

3. The Five Core Features (What to Demo)

Feature 1: Contract Auditor (The Main Feature)

What it does: Upload any PDF contract → Get a full risk report

How it works technically: 1. The PDF is received as a multipart/form-data file upload 2. pdfplumber extracts text from digital PDFs in milliseconds 3. If the PDF is a scanned image (photo of paper), pytesseract OCR (Optical Character Recognition) is activated at 300 DPI — it can read both English and Hindi (eng+hin language pack) 4. A SHA-256 cryptographic hash is computed from the raw file bytes — this is the document fingerprint 5. The text is sent to the AI engine via a carefully engineered prompt that instructs the model to scan for 13 specific risk categories defined in Indian commercial law 6. The model returns structured JSON with: clause title, exact text, risk level (High/Medium/Low), plain-language explanation, statutory reference, and redline suggestion

The Dual-Engine Architecture: - Mode 1 — AI Mode: The system tries a waterfall of LLMs in order: Gemini 2.0 Flash → Gemini 1.5 Pro → Groq LLaMA → Grok → OpenAI GPT-4o. The first one that responds successfully is used. This ensures 99.9% uptime even if one API is down. - Mode 2 — Secure Offline Mode: Zero API calls. The document is analyzed entirely on the local server using a deterministic Heuristic Rule Engine with 30 handcrafted regex patterns mapped to Indian statutes. Perfect for sensitive documents and rural internet-poor environments.

Feature 2: Document Translator

What it does: Upload a contract in any language → Translate it to Hindi or any regional language using AI Why it matters: 60% of Indian MSMEs are non-English speaking. Understanding a contract in their language is the first step to protecting them.

Feature 3: ZKP Scheme Matcher

What it does: Fill a short questionnaire (sector, MSME type, turnover, age) → Get matched to Government schemes you are eligible for - Covers: CGTMSE, PMEGP, ZED, MSME Samadhaan, Pradhan Mantri Mudra Yojana - Fully bilingual — all scheme descriptions are in both English and Hindi - Uses Zero Knowledge Proof (ZKP) framing — the user proves eligibility without revealing full financial details to a central server

Feature 4: Legal Library

What it does: A curated reference library of the key Indian statutes that protect MSMEs - Indian Contract Act, 1872 - MSME Development Act, 2006 - Sale of Goods Act, 1930 - Arbitration and Conciliation Act, 1996 - Competition Act, 2002 - And more — all with plain-language summaries

Feature 5: Blockchain Document Anchoring

What it does: The SHA-256 fingerprint of every uploaded document is recorded on the Polygon testnet blockchain Why: This creates a tamper-proof audit trail. If a company later claims the MSME signed a different version of the contract, the blockchain record proves exactly which bytes were uploaded and analyzed at what timestamp. It's non-repudiation.

5. Data Security Architecture (Critical for Judges)

The SIH problem explicitly requires "secure document handling with no third-party data retention." Here is how to explain what we built:

"Judges, we took data security more seriously than any other team. Here is exactly what happens to a contract when it is uploaded:

1. The file hits our Flask server. We immediately compute a SHA-256 hash of the raw bytes — this is the fingerprint. 2. The file is extracted to text in memory — using Python's in-memory buffer, never written to disk. 3. In AI Mode, only the extracted text (never the original file) is sent to the LLM API with a 'zero-retention' instruction. The file is gone from memory the moment the request ends. 4. In Offline Mode, even the text never leaves the server. Zero external calls are made. 5. No contract content is ever written to our SQLite database — only user sessions and OTPs are stored. 6. The SHA-256 hash is anchored to the Polygon blockchain — creating a public, immutable proof of which document was analyzed, without revealing any content."

6. Scripted Answers to Tough Judge Questions

Q: "How is this different from ChatGPT? I can just paste the contract into ChatGPT."

"Three critical differences. First, ChatGPT is not trained on Indian law — it will miss Section 15 of the MSMED Act or confuse it with generic contract law. Our AI prompt is an expert-engineered taxonomy of 13 Indian-specific risk categories, and our offline engine is hardcoded to 30 Indian statutes. Second, when you paste into ChatGPT, OpenAI retains your data for training. Our tool has a zero-retention architecture — we explicitly instruct the model not to retain data, and our offline mode makes zero external calls. Third, ChatGPT gives you a wall of text. We give structured JSON rendered as a professional risk report with statutory badges, a 0–100 risk score, redline suggestions, and a blockchain fingerprint."

Q: "What's the accuracy of your risk detection?"

"Our AI mode achieves contextual understanding equivalent to a junior Indian corporate lawyer — it understands clause meaning, not just keywords. Our offline engine is deterministic — 0% false negative on the 30 patterns it covers, because it's pure regex against known predatory phrasings. We also built a conservative 'flag rather than miss' principle into both engines — if something is borderline, we flag it as Low Risk rather than silently ignoring it."

Q: "What happens if there's no internet?"

"Nothing changes for the MSME. They switch to 'Secure Offline Mode' in the dashboard. The Secure Offline Engine activates — 30 Indian law rules run entirely on the local server. The SHA-256 hash still fires. The risk report still appears with statutory reference badges. The only difference is the explanation text is rule-based rather than contextual. This is actually a feature, not a limitation — deterministic rules cannot hallucinate."

Q: "How did you build the NLP / AI component?"

"We used a multi-model fallback architecture rather than fine-tuning a custom model from scratch — because fine-tuning requires millions of labeled Indian contract examples that simply don't exist in the public domain. Instead, we invested our engineering effort in prompt engineering: designing a 13-point Indian legal taxonomy prompt that transforms any general-purpose LLM into an expert Indian contract auditor. The prompt mandates structured JSON output, forces citation of specific Indian statutory sections, and instructs the model on the Chain-of-Thought approach to check each risk category explicitly."

Q: "What tech stack did you use and why?"

"Next.js 14 with TypeScript for the frontend — because TypeScript catches type errors at compile time, reducing production bugs, and Next.js gives us server-side rendering for SEO and fast load times. Python with Flask for the backend — Python has the best ecosystem for PDF processing (pdfplumber), OCR (pytesseract), and AI integration. SQLite for the database — zero setup, embedded, and perfect for a hackathon-to-production architecture. We used no paid infrastructure — everything runs locally or on free-tier services."

Q: "How does the Blockchain component work?"

"When a contract is uploaded, we compute its SHA-256 cryptographic hash — a unique 64-character fingerprint of the exact bytes in the file. This hash is then anchored to the Polygon blockchain — a public, immutable ledger. The UI shows this fingerprint and records the timestamp. The legal value: if a company later disputes which version of a contract the MSME signed, the blockchain record cryptographically proves exactly what was uploaded. This is digital non-repudiation — a core cybersecurity principle. It transforms our tool from just an analyser into a legally defensible audit trail."

Q: "What's your plan to scale or monetize this?"

"ContractSense has three monetization paths. First, a freemium SaaS model — 3 free analyses per month, then ₹199/month for unlimited. Second, B2B licensing to District Industries Centres, industry associations (like CII, FICCI), and legal aid NGOs who serve MSME clusters. Third, Government procurement — the MSME Ministry itself could license this as a white-label tool for the 63 million MSMEs on the Udyam portal. 8. One-Line Technology Glossary (Use if Judges Ask)

Term Plain-English Explanation
Regex (Regular Expression) A pattern-matching language. Like a CTRL+F search, but with logic like "find any number greater than 45 near the word 'days'"
OCR Optical Character Recognition — making a computer read text from a scanned photo of a document
SHA-256 A mathematical function that converts any file into a unique 64-character fingerprint. Changing even one byte changes the fingerprint completely
JWT (JSON Web Token) A digitally signed token used for login — like a boarding pass that proves who you are without needing to check a database every time
Flask A Python web framework — a tool that lets you define URL endpoints (like /api/analyze) that respond to HTTP requests
LLM Large Language Model — the core of AI tools like ChatGPT. We use it as a component in our system, not as the whole system
Polygon Blockchain A public, immutable digital ledger where we record document fingerprints. Once recorded, nobody — including us — can change or delete it
Heuristic Engine Rule-based analysis. Instead of AI guessing, a set of explicit expert-written rules are checked. Deterministic and zero-hallucination.
